Security fix: you could stay logged in after using a Download ID. A Download ID is only meant to log you in for the duration of a single download. If that download failed or was interrupted under certain conditions, the browser or download client which made the request could stay logged into the site as the owner of the Download ID. Exploiting this requires already knowing a valid Download ID. We consider this a medium priority issue and recommend that you update. A session which was left logged in before you updated is not ended by the update; it remains until it expires, according to your site's Session Lifetime setting.

Refused downloads through update streams. When download logging was enabled, refusing a download through an update stream's download link resulted in an HTTP 500 error. It now returns the expected HTTP 403 error, or redirects you if you have configured a redirection. The attempt is recorded in the download logs, and reported to Admin Tools if you have enabled banning for unauthorised download attempts.
